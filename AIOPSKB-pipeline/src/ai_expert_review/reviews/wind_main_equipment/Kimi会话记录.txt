# 风电主设备分类评审（完整设备清单）

## 任务说明

请对风电（wind power）子行业的设备分类进行全面评审。下面列出了当前 equipment_registry.md 中的**全部31项设备**及其当前分类。

请基于工程实际和知识工程两个角度，审查：
1. 当前1项主设备是否合理？是否应增加或减少？
2. 辅助设备中是否有应升级为主设备的？
3. 辅助设备与公用系统的边界是否合理？
4. 设备边界是否清晰？是否有该拆分或合并的条目？

**提示：如果你对某些设备的边界判定不确定，可以自行通过网络搜索查询行业标准和实际工程案例来辅助判断。**

## 分类原则

- **主设备**：直接参与能量转换/生产过程的核心设备，或处于主工艺链关键节点的独立大件，投资占比大、停机影响全局
- **辅助设备**：为核心设备提供支持的配套设备
- **公用系统**：全厂共用、不直接参与单台机组生产过程的基础设施

## 重点需要评估的问题

1. **风电机组作为唯一主设备是否合理？** 风电的特殊性在于风机是批量化成套设备，每台风机本身就是一个完整的能量转换单元。
2. **箱式变压器**：每台风机出口都有箱变，将低压升至35kV。它相当于风机的"发电机出口变压器"，放在辅助设备是否合适？
3. **主变压器**：火电/水电中它是主设备，风电中放在公用系统。风电升压站的主变是否应同样视为主设备？
4. **塔筒和基础**：它们更像是风机的结构部件而非独立设备。放在辅助设备是否合理？还是应归入风机的部件层（components）？
5. **GIS/断路器**：火电中GIS维持辅助设备（升压站公用），水电中GIS是主设备。风电GIS应如何处理？
6. **集电线路**：它是连接风机和升压站的电力线路，归为辅助设备还是公用系统？
7. **其他设备的分类边界**是否合理？

请给出完整的审查意见。

**评审判定：不同意当前方案。**

当前风电分类存在**主设备过度聚合**（仅1项）、**工艺链关键节点缺失**（箱变、主变未入主设备）、**整机内部子系统越位为独立设备**（塔筒、基础、风速仪等）、以及**与火电/水电评审先例的体系不一致**（主变、GIS定位偏差）。从知识工程角度，该清单会导致故障诊断时检索噪声大、可靠性统计粒度失衡。

## 一、主设备评审（应由1项增至3项）

### 1. 保留「风电机组」为主设备
**判定：同意，但须附加知识工程条件。**

风电批量化成套采购、整机吊装、整机质保的工程模式，决定了以「台套」为单元注册主设备符合行业实际。然而，**必须在知识库中强制解构为子系统（L2）和部件（L3）**，至少包含：叶轮/叶片、传动链（主轴+齿轮箱/直驱）、发电机、变流器、偏航系统、变桨系统、主轴承、塔筒、基础。否则，ISO 14224可靠性分析将无法区分齿轮箱故障与发电机故障，丧失故障诊断精度。

### 2. 箱式变压器（风电用）→ 升级为主设备
**判定：不同意当前列为辅助设备，建议升级。**

**理由：**
- **主工艺链关键节点**：处于能量流必经路径（发电机出口690V→35kV），是单台风电机组电能外送的首个升压环节，地位等同于火电的机端升压设备。
- **专属属性**：风电行业典型配置为「一机一变」，非全场共用，故障仅导致该机组停运，具备独立可靠性统计价值。
- **投资与运维量级**：虽单台容量小于主变，但全场箱变总投资占比显著，且通常独立招标、独立运维（非风机主机厂标配）。
- **类比先例**：火电评审将「发电机出口断路器(GCB)」从配电装置中拆出升级为主设备，正是因其处于机端关键节点。箱变在风电工艺链中的节点重要性不低于GCB在火电中的位置。

### 3. 主变压器 → 从公用系统升级为主设备
**判定：不同意当前列为公用系统，建议升级。**

**理由：**
- **先例一致性**：火电、水电评审均将「主变压器」列为主设备。风电场主变同样是电能外送的唯一核心枢纽，投资占比大、停机即导致全场失电，完全符合主设备定义中「投资占比大、停机影响全局」的标准。
- **「全场共用」不应成为降级理由**：火电主变亦存在两台机共用一台的配置，但仍为主设备。主变的升压功能属于能量转换/输送的核心工艺，而非「基础设施」。

**建议主设备清单（3项）：**
1. 风电机组
2. 箱式变压器（风电用）
3. 主变压器

## 二、应下沉为风电机组子系统/部件的条目

以下7项与风电机组存在**强整机从属关系**（通常由主机厂成套供货、无独立工艺流程、故障模式依附于风机），在发电厂级设备注册（equipment_registry）中独立成条会导致分类粒度失衡。建议从当前清单中移除，纳入「风电机组」的L2/L3知识节点：

| 当前条目 | 下沉理由 |
|---------|---------|
| **塔筒** | 结构支撑件，无旋转/电气动作部件；属风机结构子系统。若因采购单独招标需跟踪，应在知识库中作为「风电机组→塔筒」节点，而非独立设备。 |
| **基础** | 土建结构体，非机械设备；ISO 14224中通常作为风力涡轮机的子系统或外部结构。 |
| **润滑系统** | 风机内部子系统，服务于齿轮箱/轴承，无独立能量转换功能。 |
| **冷却系统** | 风机内部子系统，服务于发电机/变流器。 |
| **风速风向仪** | 传感器级部件，主机厂配套标准附件。 |
| **避雷系统** | 风机集成防雷设施，依附于叶片/机舱。 |
| **振动监测系统(CMS)** | 风机状态监测子系统，通常随主机采购。 |

**知识工程影响**：若保留上述条目为独立设备，故障检索时「塔筒振动」可能与「风电机组振动」产生知识冲突，推理机难以判定隶属关系。下沉后可建立明确的「整机-子系统」层级推理链。

## 三、辅助设备与公用系统的边界调整

### 1. GIS/断路器：建议从「公用系统」调至「辅助设备」
**判定：不同意当前归类。**

- **先例一致性要求**：火电评审明确「GIS维持辅助设备（火电GIS为升压站，多机组公用，不同于水电）」。风电场GIS同样位于升压站、全场多机组共用，逻辑上应与火电保持一致，列为**辅助设备**。
- **分类定义辨析**：GIS属于高压配电装置，是电气主回路设备，而非「不直接参与生产过程的基础设施」。若留在公用系统，需修正火电先例的逻辑，否则同一编码体系内出现分类歧义。

### 2. 视频监控系统：建议从「辅助设备」调至「公用系统」
当前描述未限定范围。若其为**全场级安防监控**（覆盖升压站、道路、集电线路等），则属于全场共用基础设施，应归入公用系统；若仅为**单台风机机舱内部监控**，则应下沉为风电机组子系统。按风电场常规配置，以前者为主，建议调整。

### 3. 消防系统边界需厘清
当前存在两条消防条目：
- **辅助设备(15)**：「机舱、塔筒、箱变等区域」——属于风机/箱变级
- **公用系统(29)**：「升压站内区域」——属于场级

**建议**：将(15)更名为**「风机及箱变消防系统」**，明确其与(29)「升压站消防系统」的场站边界，避免运维责任混淆。

### 4. 集电线路：维持辅助设备
**判定：同意当前归类。**

虽汇集多机电能，但集电线路通常按回路建设（每回接3~8台风机），故障影响局部，且具备线路工程属性，不属于全场共用的基础设施。类比火电评审中「高压电缆/GIL归为辅助设备」，维持辅助设备合理。

## 五、替代建议总结

### 建议的主设备清单（3项）
1. **风电机组**（整机套，知识库内必须解构为子系统）
2. **箱式变压器（风电用）**（一机一变，机端升压主设备）
3. **主变压器**（全场升压外送核心，遵循火电/水电先例）

### 建议移除/下沉的条目（7项）
塔筒、基础、润滑系统、冷却系统、风速风向仪、避雷系统、振动监测系统 → 纳入「风电机组」子结构。

### 建议调整分类边界的条目
- **GIS/断路器**：公用系统 → **辅助设备**（与火电先例一致）
- **主变压器**：公用系统 → **主设备**（与火电/水电先例一致）
- **视频监控系统**：辅助设备 → **公用系统**（按全场级安防理解）
- **消防系统(15)**：更名为**「风机及箱变消防系统」**，明确与升压站消防的边界

### 知识工程实施建议
- **编码体系**：建议采用类KKS逻辑。风机按单元编码（如WT01/WT02），箱变跟随对应风机单元；升压站设备（主变、GIS、SVG）统一归入全厂码（如0/1号厂房）。主设备升级为3项后，风电场设备注册表将形成「单元级（风机+箱变）—全厂级（主变）」的清晰拓扑。
- **故障诊断检索**：当检索「齿轮箱油温高」时，推理路径应为 **主设备(风电机组) → 子系统(传动链/齿轮箱) → 故障模式**，而非在31个平级设备中做文本匹配，这可显著降低知识图谱的歧义边。

**最终结论：当前31项清单需缩减至约24~25项顶层设备，主设备增至3项，并建立风电机组内部三级解构，方可满足跨行业可复用性与故障诊断知识检索的要求。**
