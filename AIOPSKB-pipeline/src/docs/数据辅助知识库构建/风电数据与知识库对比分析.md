# 风电：数据仓库设备分布 vs 知识库构建 对比分析

> **数据基线**：PHM 数据仓库 `alg_analysis`，风电行业（`IndustryType_FD`），近 5 年，77,413 台设备
> **对标知识库**：`src/data/power/wind/`（风电机组，三机型已完整构建：DFIG/半直驱/PMSG，2698 故障）
> **结论速览**：风电知识库的构建与监测平台数据**高度一致**。**子设备层完美吻合**，**核心部件层一致**（数据是 KB 的子集），子系统层数据无法完整验证（监测范围局限，非 KB 缺陷）。风电 KB 构建质量得到数据强印证。

## 三、三层对比（核心）

### 3.1 子设备层：✅ 完美吻合

| 数据仓库（按存量降序） | 知识库 |
|---|---|
| 双馈主传动 23,630 台（62%） | 双馈异步风电机组（DFIG） |
| 直驱主传动 9,197 台（24%） | 直驱永磁同步风电机组（PMSG） |
| 半直驱主传动 5,065 台（13%） | 半直驱（中速永磁）风电机组 |

**结论**：数据的三技术路线与 KB 三子设备**一一对应**，且存量排序合理（双馈最主流）。强证 KB 子设备划分的正确性，也印证了「只保留三大主流、剔除高速永磁/液压传动等小众机型」的裁剪决策（这些机型在数据里存量极低）。

### 3.2 部件层：🟢 核心一致（数据是 KB 的子集）

数据 12 个部件级 `devicetype`，命中 KB 部件情况：

| 数据部件 | KB 是否有对应 | KB 对应部件 |
|---|---|---|
| 叶片 / 叶片设备 | ✅ | 叶片 |
| 齿轮箱 | ✅ | 齿轮箱总成 |
| 主轴 | ✅ | 主轴总成 / 轮毂主轴法兰 |
| 变桨轴承 / 变桨轴承(超声) | ✅ | 变桨轴承 |
| 机舱 | ✅ | 机舱（振动传感器） |
| 风机 | ✅ | 散热风机（冷却系统部件） |
| 塔顶/变桨系统/变桨设备/变桨传动 | 🟡 命名差异 | KB 用「变桨轴承/变桨电机」等具体名 |

**命中率 8/12（67%），考虑命名差异后实际吻合度更高**。

**关键差异**：KB 有 **138** 个部件（远多于数据 12 个），因为：
- KB 按手册完整拆解了所有总成（含偏航齿圈/液压站/变流器功率模块/冷却水泵等）
- 数据只录入了**被振动监测覆盖的关键部件**（叶片/齿轮箱/主轴/变桨轴承等旋转/受载部件）

**结论**：数据部件 = KB 部件的**核心子集**。数据印证了 KB 对"高频受监测部件"的覆盖，KB 则在数据基础上按手册补全了完整部件树。两者互补，无矛盾。

### 3.3 子系统层：⚪ 数据无法完整验证（监测范围局限）

数据部件能明确映射到的子系统：**3/10**

| KB 10 子系统 | 数据是否有对应部件 |
|---|---|
| 风轮系统 | ✅ 叶片 |
| 传动系统 | ✅ 齿轮箱/主轴 |
| 变桨系统 | ✅ 变桨轴承 |
| 发电系统 | 🟡 发电机（数据归设备级） |
| 塔架与支撑系统 | 🟡 塔基/塔顶（部位） |
| 偏航系统 | ❌ 数据无 |
| 变流与并网系统 | ❌ 数据无 |
| 控制系统 | ❌ 数据无 |
| 冷却与散热系统 | ❌ 数据无（散热风机零星） |
| 润滑与液压系统 | ❌ 数据无 |

**原因**：偏航齿圈/变流器/控制器/冷却水泵/液压站等部件，**不是振动监测的主要对象**（多为电气/液压/控制件），故数据里没有单独 `devicetype`。

**结论**：这 7 个子系统数据缺失是**监测技术的覆盖局限**，**不是 KB 构建缺陷**。KB 按「功能分解」方法论（construct_guide §1.1）+ 风电 RDS-PP 标准构建 10 子系统是完整且正确的，数据无法验证不代表 KB 有错。

## 四、发现的分类边界问题（行业上下文）

本次对比再次暴露全局分类的行业上下文问题（同火电）：

| devicetype | 全局分类 | 风电应修正为 | 原因 |
|---|---|---|---|
| 7009 塔基 / 7008 塔顶 | 设备 | **部位（其他）** | 是测点位置，非独立设备 |
| 7007 发电机 | 设备 | **部件（发电系统）** | 风电下发电机是部件；火电下是主设备 |
| 7010 塔顶(测倾) | 部件 | **部位（其他）** | 同塔基/塔顶 |

**启示**：`发电机/风机/塔基` 等存在**跨行业层级漂移**。建议后续：
- 分类脚本增加「行业修正规则」（如风电下 `发电机→部件`，火电下 `发电机→主设备`）
- 或对边界设备在 CSV 标注「行业相关」，由人工按行业复核

## 五、总体结论

| 层 | 一致性评级 | 说明 |
|---|---|---|
| **子设备** | ✅ 完美 | 数据三技术路线 = KB 三子设备，存量排序合理 |
| **部件** | 🟢 良好 | 核心部件一致，数据是 KB 的合理子集（138 vs 12） |
| **子系统** | ⚪ 无法验证 | 数据覆盖 3/10，缺失项是监测局限非 KB 缺陷 |
| **设备** | 🟡 部分 | 数据只覆盖整机+核心，KB 25 个设备更全（含升压站等） |

**风电知识库的构建质量得到监测平台数据的强印证**，尤其是子设备层（最关键的判定）完美吻合。KB 在子系统/部件层的"超出数据范围"的部分，是按标准+手册+专家经验合理扩展，符合 `construct_guide.md` 的构建方法论。

> **对比火电**：火电数据缺位（主设备 0），KB 只能靠标准；风电数据富集，KB 得到数据全面印证。这验证了「数据富集行业（风电/石化/钢铁）可数据驱动，数据弱覆盖行业（火电/水电/核电）须标准驱动」的分层策略。
