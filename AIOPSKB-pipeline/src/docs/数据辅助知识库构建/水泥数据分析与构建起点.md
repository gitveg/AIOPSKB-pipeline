# 水泥行业：设备生成优先级参考

> **数据基线**：PHM 数据仓库 `alg_analysis`，水泥（`industry_cn = 水泥`），近 5 年，17,072 台设备 / 78 家企业 / 130 型号
> **数据质量分级**：**C 级（偏弱）**——设备级仅占 28.4%（已分析行业最低），"其他"类 46.5%，数据**仅作旁证**，以标准/专家为主
> **本文作用**：为 pipeline 的**设备生成提供优先级排序**——按数据存量从大到小，告诉 pipeline"优先生成哪些设备类型"
> **不做什么**：不决定设备清单的具体内容、不决定设备粒度、不分子行业。这些由 pipeline 按 `construct_guide` + 专家评审完成

---

## 一、定位与边界

| 项 | 说明 |
|---|---|
| 本文提供 | 设备生成的**优先级**（基于监测平台存量） |
| 本文不提供 | 具体设备清单、设备粒度、子行业划分 |
| 数据适用范围 | **动设备**（风机/磨机传动/输送/破碎等旋转设备）—— 数据有效 |
| 数据不适用 | **静设备**（预热器/分解炉/篦冷机本体）—— 数据缺位，须标准 |
| 子行业 | **不拆**（详见第二节） |
| 旧 KB | 水泥 KB 尚未构建，无历史包袱 |

> **核心提示**：监测平台（容知 PHM）是振动监测，**只覆盖旋转动设备**。水泥的预热器/分解炉/篦冷机等静设备数据基本为 0，**不能用数据排优先级**，pipeline 须按水泥标准（JC/T 733 回转窑、GB/T 26583 水泥回转窑、JC/T 系列磨机等）另行排期。注意：回转窑有旋转部件（筒体/轮带/托轮/传动），属"半静半动"，**有部分监测数据**——这点与钢铁纯静设备（高炉 0 数据）不同。

---

## 二、子行业决策：不拆（水泥是一体化连续流程）

水泥**不需要子行业**，比钢铁/石化更明确：

| 判据 | 结论 |
|---|---|
| ① 工艺形态 | 水泥是**一条连续生产线**（两磨一烧：生料磨 → 回转窑烧成 → 水泥磨），各工段物理上连成一体，无独立边界 |
| ② 对比钢铁 | 钢铁至少有炼铁/炼钢/轧钢的物理分隔（不同车间），水泥连这点分隔都没有 |
| ③ 数据无技术路线维度 | 子设备层 0 型号，无技术路线聚类 |

**结论**：水泥直接从设备枚举开始。工艺上可按"**生料制备 / 烧成 / 熟料冷却 / 水泥粉磨 / 包装**"五大工段理解设备功能归属（见第八节），但这只是功能分组，**不构成子行业层**。

## 八、给 pipeline 的使用说明

1. **按"两磨一烧"工艺理解设备功能归属**（不构成子行业，仅功能分组）：
   - **生料制备**：破碎机（圆锥/反击/锤式）→ 生料磨（立磨/球磨）→ 选粉机
   - **烧成**：预热器 → 分解炉 → **回转窑** → **篦冷机**
   - **水泥粉磨**：水泥磨（球磨/辊压机）→ 选粉机
   - **输送/包装**：斗式提升机 / 斜拉链 / 螺旋输送 / 包装机
2. **通用动设备（簇一）可与钢铁/石化共享通用组件库**（§7.1）。
3. **静设备（第六节）单独排期**——篦冷机/预热器/分解炉数据缺位，须按水泥标准（JC/T 733、GB/T 26583、JC/T 磨机系列）+ 手册构建，**不要混入数据优先级**。
4. **部件层先甄别误判**（第五节 5.2）——斗式提升机/辊压机/管磨/汽轮发电机要先重判为设备，再建部件树。
5. **数据质量警示**——水泥设备级仅 28.4%（最低），优先级清单只作"哪些设备真实存在"的旁证，**设备完整性须以水泥工艺标准 + 专家评审为准**。
6. **不分子行业**——水泥一体化连续流程，直接设备枚举。
