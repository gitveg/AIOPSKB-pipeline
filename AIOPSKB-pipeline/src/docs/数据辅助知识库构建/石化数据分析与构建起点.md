# 石化行业：设备生成优先级参考

> **数据基线**：PHM 数据仓库 `alg_analysis`，石化（`IndustryType_SH`），近 5 年，66,746 台设备
> **本文作用**：为 pipeline 的**设备生成提供优先级排序**——按数据存量从大到小，告诉 pipeline"优先生成哪些设备类型"
> **不做什么**：不决定设备清单的具体内容、不决定设备粒度、不分子行业。这些由 pipeline 按 `construct_guide` + 专家评审完成
> **旧 KB 处理**：石化旧的 6 子行业分类（石油炼制/化肥/合成树脂等）数据质量差，**已全部归档**。石化直接从设备枚举开始，不分子行业

---

## 一、定位与边界

| 项 | 说明 |
|---|---|
| 本文提供 | 设备生成的**优先级**（基于监测平台存量） |
| 本文不提供 | 具体设备清单、设备粒度（独立设备 vs 子设备）、子行业划分 |
| 数据适用范围 | **动设备**（泵/压缩机/风机/搅拌等旋转设备）—— 数据有效 |
| 数据不适用 | **静设备**（换热器/塔器/反应器）—— 数据缺位，须标准 |
| 旧 KB | 6 子行业已归档，石化整体直接枚举设备 |

> **核心提示**：监测平台（容知 PHM）是振动监测，**只覆盖旋转动设备**。石化的换热器/精馏塔/反应器等静设备数据基本为 0，**不能用数据排优先级**，pipeline 须按石化标准（GB150/GB151/SH/T）另行排期。

## 四、数据外的设备（静设备，优先级不适用，须标准）

这些是石化核心设备，但**振动监测覆盖不到，数据基本为 0**。pipeline 不能用数据排优先级，须按石化标准 + 手册**单独排期**：

| 静设备 | 数据台数 | 说明 |
|---|---|---|
| 换热器（管壳式） | 6 | 数据缺位，须 GB151 |
| 冷凝器 | 9 | 同上 |
| **精馏塔 / 吸收塔 / 解析塔** | **~0** | 石化核心分离设备，完全无数据 |
| 蒸发器 / 结晶器 | 极少 | 无数据 |
| 反应釜 / 反应器 | 136 | 有少量数据，但本质静设备 |
| 容器 / 储罐 | 极少 | 无数据 |

> **警示**：千万别因为"换热器只有 6 台数据"就认为它不重要——它和数据缺位是两回事。石化 KB 的静设备必须靠标准构建，与数据优先级解耦。

## 六、给 pipeline 的使用说明

1. **按 P0 → P1 → P2 → P3 顺序生成设备**——存量越大越优先，证据越强（企业数越多越代表行业普遍性）。
2. **静设备（第四节）单独排期**——数据缺位不代表不重要，须按石化标准（GB150 压力容器、GB151 换热器、SH/T、HG/T）+ 手册构建，**不要混入数据优先级**。
3. **第五节的异常项先清洗**——环冷机跨界、通用名归并、未分类剔除，避免污染设备枚举。
4. **设备粒度由 pipeline 决定**——例如"螺杆泵"数据有单/双/三 3 个型号，是合并为一个设备还是拆分，由 pipeline 按 `construct_guide` 五原则 + 专家评审判定，本文不预设。
5. **不分子行业**——石化整体枚举，通用动设备（泵/压缩机/风机）跨工艺复用。
