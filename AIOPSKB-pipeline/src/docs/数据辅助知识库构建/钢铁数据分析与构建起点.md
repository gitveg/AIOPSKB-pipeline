# 钢铁行业：设备生成优先级参考

> **数据基线**：PHM 数据仓库 `alg_analysis`，钢铁（`industry_cn = 钢铁`），近 5 年，37,872 台设备 / 166 家企业 / 225 型号
> **数据质量分级**：**C 级**（分散、未分类 35.4%，比石化 B 级更难啃）—— 参照价值打折，数据仅作旁证，以标准/专家为主
> **本文作用**：为 pipeline 的**设备生成提供优先级排序**——按数据存量从大到小，告诉 pipeline"优先生成哪些设备类型"
> **不做什么**：不决定设备清单的具体内容、不决定设备粒度、不分子行业。这些由 pipeline 按 `construct_guide` + 专家评审完成

---

## 一、定位与边界

| 项 | 说明 |
|---|---|
| 本文提供 | 设备生成的**优先级**（基于监测平台存量） |
| 本文不提供 | 具体设备清单、设备粒度、子行业划分 |
| 数据适用范围 | **动设备**（泵/风机/轧机传动/辊/电机等旋转设备）—— 数据有效 |
| 数据不适用 | **静设备**（高炉/转炉/加热炉/连铸机本体）—— 数据缺位，须标准 |
| 子行业 | **不拆**（详见第二节） |
| 旧 KB | 钢铁 KB 尚未构建，无历史包袱 |

> **核心提示**：监测平台（容知 PHM）是振动监测，**只覆盖旋转动设备**。钢铁的高炉/转炉/电炉/连铸机/加热炉等核心工艺静设备数据基本为 0，**不能用数据排优先级**，pipeline 须按钢铁标准（GB 50431 高炉、GB 50478 转炉、YB/T 系列等）另行排期。

---

## 二、子行业决策：不拆（但理由与石化不同）

钢铁**有**清晰的工艺边界（烧结/球团 → 炼铁 → 炼钢 → 轧钢），教科书式分明，这点和石化（工艺边界模糊）不同。但综合判断**当前不分子行业**：

| 判据 | 结论 |
|---|---|
| ① 监测数据构成 | 以**通用动设备**（泵/风机/电机/轧机传动）为主，这些跨工艺复用，拆子行业无收益 |
| ② 核心工艺设备数据 | 高炉/转炉/连铸机/加热炉等是**静设备**，数据缺位，**无法靠数据按工艺划分** |
| ③ 数据中无技术路线维度 | 子设备层仅 1 台（忽略），钢铁设备不存在"双馈/直驱"式的技术路线聚类 |
| ④ 管理复杂度 | 直接设备枚举即可，分子行业徒增目录层级 |

**诚实提醒**：将来若 KB 规模扩大、需要按工艺组织，"**炼铁 / 炼钢 / 轧钢**"是天然划分（烧结/球团/焦化可作为炼铁子环节或独立）。但当前数据驱动构建阶段，**直接枚举设备**更顺——轧钢线的棒线轧机/板材轧机/管材轧机/冷轧/热轧在数据里是**平级独立设备**（各自独立 `devicetype`），不是某"轧机"大类的子设备，应直接列为多个设备。

## 四、设备生成优先级清单（核心交付）

## 八、给 pipeline 的使用说明

1. **按簇 × 优先级生成设备**：通用动设备（簇一）可与石化共享通用组件库（§7.1）；轧钢线设备（簇二）是钢铁必建特色；原料/输送/起重（簇三）按需。
2. **静设备（第六节）单独排期**——数据缺位不代表不重要，须按钢铁标准（GB 50431 高炉、GB 50478 转炉、YB/T 系列、GB 50579 连铸等）+ 手册构建，**不要混入数据优先级**。
3. **部件层善用数据（第五节）**——钢铁部件级数据是各行业最丰富的之一，张力辊/导辊/锥箱/齿轮箱等可直接作为部件候选，这是钢铁相对石化的构建优势。
4. **第七节异常项先清洗**——"其他"类 43.8% 是数据质量警示，通用名归并、未分类/单企业剔除，避免污染设备枚举。
5. **设备粒度由 pipeline 决定**——轧机系列（棒线/板材/管材/冷轧/热轧）是多个独立设备还是归并为"轧机"大类，由 pipeline 按 `construct_guide` 五原则 + 专家评审判定，本文不预设。
6. **不分子行业**——钢铁整体枚举。将来若需工艺维度，"炼铁/炼钢/轧钢"是备选划分（第二节）。
