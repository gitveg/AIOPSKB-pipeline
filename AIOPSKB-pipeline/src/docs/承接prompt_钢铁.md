## 3. 火电+石化沉淀的可复用成果（钢铁直接受益）

### 3.1 C方案（跨行业复用）★钢铁通用动设备簇核心复用

**C方案 = 结构层复制 + 故障层行业感知（industry-aware）重新生成**（详见 construct_guide §10）。钢铁的**簇一通用动设备**（离心泵/离心风机等）与石化高度重叠，而石化已从火电复用过——钢铁可**直接 C方案复用石化库**：

| 钢铁设备 | C方案源（已建好） | 复用方式 |
|---------|---------------|---------|
| 离心泵 | 石化 `离心泵/`（卧式/立式筒袋/高速/屏蔽/磁力 5 子设备）| 结构层复制，故障层用钢铁 prompt 重生 |
| 离心风机 | 石化 `风机/离心风机/` | 同上 |
| 压缩机（若有）| 石化 `压缩机/` | 同上 |

> **C方案铁律**（§10.1）：结构层可复制，**故障层必须用目标行业 prompt 重新生成**（直接复制故障层会引入工况污染）。复用后**必须经三AI评审**（会继承源行业缺陷）+ **工况污染治理**（石化术语→钢铁术语）。

### 3.2 设计哲学与粒度统一规则（construct_guide §8，v4.0 新增）

钢铁结构层构建必须遵守这 5 条生成时硬约束（LLM 通病，已验证）：

1. **电气元件粒度**（§8.1）：PLC/变频器=部件不拆内部模块；按钮/端子=电控柜零件；不与机械总成粒度失衡
2. **标准紧固件不单列**（§8.2）：螺栓组/键/卡环不作独立零件节点
3. **易损标识判定**（§8.3）：传感器/密封/滤芯=是；机壳/机身/柜体=否
4. **执行机构归属**（§8.4）：轧钢液压缸/执行器归工艺机械侧，不归电气控制
5. **核心承载件必建**（§8.5）：**轧机机架/轧辊/压下机构/轴承座、卷取机卷筒**等核心承载件必须建，缺失即评审"致命"级

### 3.3 故障层治理机制（construct_guide §9）

故障层生成后的标准治理链（DRY-RUN → --apply 两阶段）：

```
validate_kb.py --stage 4  →  _fix_d1_cat_swap --apply  →  fix_fault_categories
→  重生成整列错位文件(--force --comp)  →  _fix_d8_level --apply  →  _fix_d5_conf --apply
→  D1顿号→分号  →  工况污染核查  →  validate_kb.py --stage 4（目标0阻断错误）
```

治理脚本（`src/scripts/_fix_*.py`）：`_fix_d1_cat_swap`（D1/类别对调）、`fix_fault_categories`（类别白名单）、`_fix_d8_level`（D8标注）、`_fix_d5_conf`（D5置信）、`_fix_maint_conf`（维护/报废冲突）。

> **第一性原理**（§9.6）：治理脚本只兜底偶发偏差，系统性问题必须改 prompt。**钢铁可能有特有治理值**（轧钢工艺设备的 D1/类别），治理时按需扩充 FIXES 字典。

### 3.4 三AI评审（ai_expert_review，C方案+新生成必需把关）

```bash
# 钢铁结构树评审（钢铁无子行业，设备类型作 --sub）
python src/ai_expert_review/AI_Expert.py review --layer structure --industry 冶金 --sub 轧机 --equip 棒线粗中轧机
```

### 3.5 旋转机械"单设备+结构子设备"范式（火电+石化验证）

故障机理通用的旋转机械，按"结构路线"合并为单设备（而非按功能/系统拆碎），工况特异在 D5 参数层标注。钢铁通用动设备簇按此范式。

## 6. 关键技术约定（务必遵守）

1. **故障类别**只从 `failure_categories.yaml` 白名单选（禁自创）
2. **D1物理属性**：机械/电气/绝缘/热/化学/控制/环境（多选用`;`分隔，禁顿号）
3. **17列故障表**：D1-D15 顺序固定；D11-D15 选填但须带置信标注
4. **设计哲学5规则**（§3.2）：电气元件粒度、紧固件不单列、易损标识、执行机构归属、**核心承载件必建**（轧机机架/轧辊/压下机构/卷筒）
5. **部件/零件标准**：三是否判定（可独立拆+独立故障+独立更换）；轴承方案B（大型独立=部件，嵌入式=零件）；禁"总成"后缀/禁"XX本体"作零件；**零件行部件列填归属部件名**（非"—"）
6. **故障跨层**：部件级只整体性失效，禁指向零件；因果链只挂根因
7. **三层结构**：子系统（无faults）→ 部件（总成级故障）→ 零件（具体失效）
8. **设备层无"系统"条目**（§3 治理判据）：单体设备或真公用域，避免功能域聚合
9. **编码**：段式 `{行业2}[-子行业2]-设备3-子设备3-子系统3-部件3-零件3-故障3`；钢铁无子行业，编码如 `MT-001-001-001-001-000-001`。导出期生成
10. **置信标注**：D5参数 + D11-D15 每条带"置信：标准值/经验值/待核实"；禁伪造标准号
11. **命名**：部件/零件名禁"/"；跨子系统 MECE 不重复
12. **工况污染治理**（C方案专用）：复用石化库后，石化术语（API/SH/T、易燃易爆、GB 30871 特殊作业）须清洗为钢铁术语（YB/T、高温粉尘重载、轧钢工艺介质）。**钢铁库工况污染=0**

## 8. 经验教训（风电+火电+石化沉淀，钢铁避免重蹈）

1. **抽样≠批量**：单设备验证通过 ≠ 全量合规，必须全量 validate
2. **表面通过陷阱**：validate stage 对目录只查根目录不递归 → 用 `validate_kb.py --target <设备目录>` 全量校验
3. **整列错位**：LLM 漏填"故障类别"列致整行左移（列数<17），`_fix_d1_cat_swap` 无法修复 → `--force --comp <部件名>` 重生成，顽固文件手动 Edit（§9.4）
4. **C方案继承缺陷**：复用石化库会继承石化（及火电）原版缺陷 → **必须经三AI评审**（§3.4）
5. **新生成漏核心承载件**：DeepSeek 倾向生成运动件，漏静止承载件（轧机机架/轴承座/卷筒）→ **必须经三AI评审**（§8.5）
6. **工况污染**：C方案复用后源行业术语残留 → 扫描+白名单映射清洗，目标行业术语计数=0（§9.5）
7. **harness 后台 bash 不稳定**（turn 结束被 kill）→ 长任务用 `nohup python ... > /tmp/x.log 2>&1 &` 脱离 harness；最后 1-2 条用前台阻塞跑（timeout 480s）
8. **fault phase 加速**：`--workers 3` 并行；fault 默认跳过已生成，kill 后续跑只补未完成
9. **GLM 慢**（~2分钟/项，2轮）；GLM 内容安全过滤（code 1301）→ DeepSeek 兜底
10. **真实有效**：dry-run→apply→复验，关键改动加自检兜底，**不接受表面通过/循环论证/数据污染**（用户底线）
11. **设备粒度先决策**：旋转机械按结构路线合并（省 token 不损诊断）；轧机系列按故障机理同质性判定独立 vs 合并

## 9. 如何运行

```bash
# 【决策点1确认后】如用"钢铁"，先在 config.py INDUSTRY_CODES 补 "钢铁": "MT"
# 钢铁不分子行业，命令无 --sub

# 单设备结构层（DeepSeek，轧钢新生成）
python src/pipeline/main.py 钢铁 --phase component --equip 棒线粗中轧机

# 单设备故障层（GLM，17列，workers=3 加速）
python src/pipeline/main.py 钢铁 --phase fault --equip 棒线粗中轧机 --workers 3

# 结构树三AI评审（新生成/C方案必需，钢铁无子行业 --sub 传设备类型）
python src/ai_expert_review/AI_Expert.py review --layer structure --industry 钢铁 --sub 轧机 --equip 棒线粗中轧机

# 校验（用 --target 全量，勿依赖 stage 表面通过）
python src/scripts/validate_kb.py --target src/data/钢铁/棒线粗中轧机

# 治理（DRY-RUN 再 --apply）
python src/scripts/_fix_d1_cat_swap.py src/data/钢铁/棒线粗中轧机 --apply
python src/scripts/_fix_d8_level.py src/data/钢铁/棒线粗中轧机 --apply
python src/scripts/_fix_d5_conf.py src/data/钢铁/棒线粗中轧机 --apply
python src/scripts/_fix_maint_conf.py src/data/钢铁/棒线粗中轧机 --apply

# 导出（md→json→csv/xlsx，已参数化）
python src/scripts/md_to_json.py src/data/钢铁 > src/data/钢铁/knowledge_base.json
python src/scripts/json_to_csv.py src/data/钢铁/knowledge_base.json src/data/钢铁/knowledge_base
```

**C方案复用石化库（簇一通用动设备）**：
```bash
# 1. 复制石化结构层到钢铁
cp -r src/data/petrochemical/离心泵 src/data/钢铁/离心泵   # 结构层直接拷
# 2. 故障层删除，用钢铁 prompt 重新生成（删除 faults/ 或 --force）

# 4. 工况污染治理（石化术语→钢铁）
# 5. validate + 治理链
```

**前置**：`.env` 配 `DEEPSEEK_API_KEY`（structure+verifier）、`LITE_LLM_DEEPSEEK_API_KEY`+`LITE_LLM_BASE_URL`+`LITE_GLM_MODEL`（GLM主力）。**DeepSeek 配额紧，仅 Phase 3 结构用**。

## 11. 已知问题/注意

- **行业名/代码不一致**：数据/用户用"钢铁"，config.py 是"冶金"=MT。开工先确认（决策点1）
- 钢铁 **C 级数据**（未分类35.4%、"其他"43.8%）：数据仅旁证，以标准/专家为主，**不能简单按 devicetype 倒排设备清单**，必须人工甄别
- 钢铁 **静设备数据为 0**（高炉/转炉/连铸机/加热炉）：不能用数据排优先级，须按 GB 50431/GB 50478/GB 50579/YB/T 标准构建，不混入数据优先级
- **md_to_json.py EQ_SLUGS 无钢铁设备**：导出前需补充轧机/卷取机等设备→英文/中文名映射（或确认导出逻辑用中文名）
- `_fix_d1_cat_swap.py` 等 FIXES 字典是火电+石化积累，**钢铁轧钢设备可能有特有值**（如轧辊/卷筒相关 D1/类别），治理时按需扩充
- C方案复用石化库 → **工况污染治理是硬指标**（石化术语在钢铁库计数=0）
- 钢铁设备属性：主设备=高炉/转炉/轧机（工艺核心），通用动设备（泵/风机）=辅助设备——与石化"几乎全辅助设备"不同
