## 1. 改造目标

### 1.1 改造项2：结构分解层

将部件层的**任意深度父部件/子部件树**拆为**固定三层语义结构**：

```
子系统（Sub-system）→ 部件（Component）→ 零件（Part）
```

映射 ISO 14224 的 Sub-unit → Component/Maintainable item → Part 层级。

**核心约束**：
- 固定三层语义，不允许自由"子部件"层级
- 允许短链（零件列填"—"）
- 禁止为填满三层虚构零件
- 子系统 ≠ 子设备（正交的轴：功能分解 vs 技术路线变体）

### 1.2 改造项3：属性挂载规则

| 结构层 | 名称+描述 | 易损标识 | 故障 | 维护方法 | 报废方法 |
|--------|----------|---------|------|---------|---------|
| 子系统  | ✓        | —       | ✗    | ✗       | ✗       |
| 部件    | ✓        | ✓       | ✓(总成级) | ✓   | ✓       |
| 零件    | ✓        | ✓       | ✓(具体失效) | ✗  | ✗       |

## 3. 设计决策记录

### 3.1 不使用 `--new-format` 参数（用户决策）

**初始设计**：添加 CLI `--new-format` 参数，新旧格式通过参数切换。

**用户反馈**："为啥要加 new-format 呢，我们当前的改造直接覆盖旧模式就好了"

**最终决策**：
- 生成侧（pipeline）：**完全移除** `--new-format`，新格式是唯一模式
- 读取侧（脚本）：**保留** `is_new_format()` 检测，用于向后兼容读取旧数据
- 理由：改造目标是彻底替换旧模式，不存在"回退到旧格式"的场景

### 3.2 格式检测方式

使用 `sub_system.md` 文件是否存在作为新/旧格式的唯一判断依据，而非目录名或文件内容特征。理由：
- sub_system.md 是新格式的核心新增文件，不存在于任何旧格式数据中
- 检测简单可靠，不依赖内容解析

### 3.3 向后兼容范围

所有下游脚本保留旧格式处理分支，但仅用于**读取**：
- `validate_kb.py`：可校验旧格式数据
- `md_to_json.py`：可转换旧格式数据
- `json_to_csv.py`：可导出旧格式数据
- `track_progress.py`：可统计旧格式数据

生成侧不保留任何旧格式代码路径。

## 6. 跨子系统MECE去重改造（2026-06-08）

> **背景**：v1 测试数据显示凝汽器"管板"同时出现在"冷凝换热管束系统"和"冷却水流通与密封系统"。经用户与Opus讨论，确认严格MECE是正确方向，由Opus产出完善方案文档。
> **方案文档**：`src/docs/知识库架构改造/改造项2-3生成质量完善方案（跨子系统MECE）.md`

### 6.1 改造方案：三道防线

| 防线 | 机制 | 层级 | 说明 |
|------|------|------|------|
| 防线1 | 生成时避让（prompt） | 生成侧 | component prompt 注入 `claimed_parts` + `all_sub_systems`，LLM 知道前序子系统已认领的件 |
| 防线2 | 生成后仲裁（pipeline） | 生成侧 | Phase 3.2 全部子系统生成完毕后，`_dedup_cross_subsystem()` 调用LLM做归属判定，删除非owner行，输出审计日志 |
| 防线3 | 校验拦截（validate） | 校验侧 | `check_cross_subsystem_dup()` 扫描所有子系统的 components.md，撞名即报 ERROR |

### 6.2 代码改动

| 文件 | 改动内容 |
|------|---------|
| `collector.py` | component prompt 增加 MECE 归属规则 + 兄弟清单注入 + 来源口径约束；sub_system prompt 增加边界互斥 |
| `orchestrator.py` | 新增 `_extract_part_names()`；Phase 3.2 循环注入 `claimed_parts`/`all_sub_systems`（含断点续跑解析）；新增 `_dedup_cross_subsystem()` 设备级仲裁 + 审计日志 |

| `judge.py` | component 审查增加第13维度：跨子系统MECE合规，注入 claimed_parts 感知 |
