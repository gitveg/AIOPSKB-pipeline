1. 设备名称 这个叫法不对，真正的现场的设备名称往往是具体的设备，比如“主变压器H101”。当前的设备名称（锅炉、发电机等等），应该叫做“设备类型”；当前的设备类型（主设备、辅助设备和公用系统），应该叫做“设备属性”或者啥的。
2. 部件层的分类会出现一些问题，比如锅炉设备下还有部件叫锅炉？对于部件的逻辑结构我们当前还没有严格的去审查和保障，我觉得可以把设备层的三AI评审模块借鉴一下，不过prompt要变一下，要针对部件的分类逻辑结构的审查。然后部件层下的部件有些太大了，比如齿轮箱、发电机。真正严格意义下的部件，应该要再细一点。 
3. 故障信息加几栏和检维修相关的：
    - 用工需求（比如仪表检维修高级工1名、工艺维护1名；预计工时4-6h）
    - 工机具（比如防爆工具套装、扭力扳手、数字万用表）
    - 备件用料（柔性石墨填料环、高温润滑脂）
    - 安全注意事项（比如涉及高温、高压或有毒有害介质时，作业人员须佩戴正压式空气呼吸器、防化服及防护面罩，设专人连续监护，并配备应急冲洗及救援装备。拆卸气动执行机构前必须关闭气源并排空营路余压至0MPa，防止弹簧储能突然释放或高压气体伤人:电动执行机构须验电确认无电后方可作业。）
    - 验收标准（阀门全行程动作灵活，无卡涩、无跳动、无异响，开关时间符合设计值(如DN80气动调节阀全行程≤30s.DN150≤45s)智能定位器校准后线性度误差≤±1.0%，回差≤0.8%，死区≤0.5%;DCS反馈信号与就地机械开度指示偏差≤±2%。填科函密封性能达到ANSVFC170-2 Clas V级标准(公称通径≤DN50时泄漏量≤0.15ml/min;>DN50时≤0.45ml/min) ，保压30min无可见渗漏。连续自动运行72小时无报警、无异常波动，控制系统阶跃响应超调量≤10%，调节过程稳定时间满足工艺控制要求。检修技术资料完整，包括卡涩根因分析、更换备件清单及序列号、校准原始数据、验收签字记录。）
4. 故障信息中的故障类别可以删除，当前的故障类别本质是物理属性类别，可以改名叫做“物理属性”，实际上是否有用需要分析。 然后新的“故障类别”这一列放一些公司当前监测平台已有的故障分类，比如不平衡、保持架、松动、轴承。 这个我觉得需要直接静态由一个文件维护，定死，不要让pipeline 的LLM去生生成
