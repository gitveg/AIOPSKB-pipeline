## 1. 改造目标

把知识库从"故障诊断字典"升级为"完整运维工作流手册"，在故障表 D10 之后追加 5 个检维修维度列，使故障表从 **12 列扩展到 17 列**。

### 1.1 新增 5 列定义（编号 D11-D15，续接 D1-D10）

| 新列（编号）| 表头/JSON列名 | 内容 | LLM 可靠性 | 置信要求 |
|------|------|------|-----------|---------|
| D11 用工需求 | `D11 用工需求` / `D11_用工需求` | 工种+人数+工时（如"钳工2名、管工1名；工时6-8h"）| 低（经验估算）| 标"经验值" |
| D12 工机具 | `D12 工机具` / `D12_工机具` | 通用工具类目（防爆工具套装、扭力扳手、万用表）| 中 | 通用项"经验值" |
| D13 备件用料 | `D13 备件用料` / `D13_备件用料` | 备件/耗材通用名（柔性石墨填料环、高温润滑脂）| 低（OEM 强相关）| 通用名"经验值"，型号现场补 |
| D14 安全注意事项 | `D14 安全注意事项` / `D14_安全注意事项` | HSE/特种作业规程 | 较高 | 有标准依据标"标准值"并引用（AQ/DL/T 等）|
| D15 验收标准 | `D15 验收标准` / `D15_验收标准` | 检验规范、量化验收指标 | 较高 | 有标准依据标"标准值"并引用（DL/T、GB/T 等）|

**编号约定**（与 D1-D10 完全一致）：表头显示 `D11 用工需求`（D编号+空格+中文）；JSON/CSV 列名 `D11_用工需求`（D编号_中文）；内部短 key `D11`（validate headers/orchestrator key_map 用）。这5列纳入统一 D 维度体系（D1-D15），而非无编号的独立列。

**设计原则**：5 列做成**独立维度列**（便于工单系统单独提取"用工需求"等），**不塞进 D8**；复用 D5 置信标注机制（标准值/经验值/待核实）；RAG 输出时注明"参考值，需对照现场实际"（OEM 强相关，准确率天然低于诊断列）。

## 2. Token 测试结论（关键决策：单段生成，无需分段）

改造方案 §6.3 担心 17 列单条 token 消耗过大、可能需分段生成。**实施前实测验证**（`token_test_retrofit6.py`）：

| 指标 | 实测 | 判断阈值 |
|------|------|---------|
| 输出 token | ~2295 | max_tokens=8192 |
| **使用率** | **28.0%** | <60% → 单段 |
| 表头列数 | 17 | 17 ✓ |
| 数据行列数 | 17 | 17 ✓ |
| 表格完整性 | 完整（5 条故障）| ✓ |

**结论：单段生成完全可行，使用率仅 28%**。即使故障数翻倍（10 条）也只用 ~56%，远低于上限。因此 **collector 无需拆分两段调用，orchestrator 无需分段改造**，大大简化实施。LLM 在 8192 token 内可稳定输出完整 17 列表格，且 5 列内容质量高（置信标注正确、标准号引用合理，如"水压试验保压30min无泄漏；凝结水硬度≤2.0μmol/L（置信：标准值 GB/T 12145-2016）"）。

## 6. 关键技术约定（改造6 新增，补充承接 prompt §5）

11. **故障表 17 列**：`故障名称 | 故障类别 | D1-D15`。检维修5列为 **D11-D15**（D11用工需求/D12工机具/D13备件用料/D14安全注意事项/D15验收标准），在 D10 之后，顺序固定。编号续接 D1-D10，纳入统一 D 维度体系。
12. **D11-D15 选填**：允许"—"，但填写时必须带置信标注（复用 D5 机制）。
13. **置信标注**：D11/D12/D13 通常标"经验值"；D14安全/D15验收鼓励标"标准值"并带标准号（DL/T 869、GB/T 12145 等）。禁止伪造标准号。
14. **单段生成**：17 列在 max_tokens=8192 内使用率仅 28%，无需分段（实测，非拍脑袋）。
15. **格式检测**：validate 通过表头"D11/D15"存在性识别 retrofit6（17列），向后兼容 12/11 列。
16. **D1 取值校验**（改造6补）：`check_d1_enum` 校验 D1 取值在 机械/电气/绝缘/热/化学/控制/环境 内（多选用;分隔），防止 LLM 自创非枚举值（如"物理"）。

## 7. 顺带修复的既有问题（部分评审发现）

- **5列缺 D 编号（评审指出）**：初版5列用裸列名（用工需求等），未纳入 D 维度编号体系。已统一为 D11-D15（表头 `D11 用工需求`、JSON/CSV `D11_用工需求`、内部 key `D11`），与 D1-D10 完全一致。全链路8文件同步更新。
- **D1 取值校验缺失**：validate_kb 无 D1 物理属性枚举校验，导致真实生成数据中 D1='物理'（应为机械/电气/绝缘/热/化学/控制/环境）漏检。新增 `check_d1_enum`，并修正冷凝管堵塞的 D1（物理→机械）。
- **json_to_csv FAULT_DIMS 误纳 D11-D15**：`FAULT_DIMS = [c for c in COLUMNS if c.startswith("D")]` 在 D11-D15 加入后会把检维修列误算入诊断维度。改为排除 `D11_~D15_` 前缀，保持 FAULT_DIMS 只含 D1-D10。
- **orchestrator `run_fault` comp_filter 失效**：参数接收但未用于过滤，导致 `--comp` 在 fault 阶段无效（处理全部部件）。改为在 task 收集后按 `comp_name` 过滤。这让单部件试点生成可行。
- **construct_guide `_consolidate` fault 格式串笔误**："禁止自创。。第一列"（双句号）顺手修正。
