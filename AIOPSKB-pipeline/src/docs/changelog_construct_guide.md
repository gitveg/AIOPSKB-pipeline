## v2.3 (2026-05-19)

基于 `docs/construct_guide的审查意见（Claude）.md` 的AI专家审查意见，采纳以下5项高优先级改进：

### 改动1: D2 故障等级增加判定标准表

**对应审查意见**: 1.2 — D2缺乏判定标准，填写者主观性过强

**变更内容**:
- D2说明列改为 `轻微/一般/严重/危急。判定标准见下方D2等级表`
- 在 D1-D9 维度表后新增 `D2 故障等级判定标准` 块引用表：
  - 危急：须立即停机，继续运行有人身安全风险或设备失效风险
  - 严重：应在72小时内安排处理，设备功能显著降级
  - 一般：可在下次计划检修前处理，设备功能轻微降级
  - 轻微：可在本检修周期内跟踪观察，不影响正常运行

### 改动2: D1 多选分隔符规范化

**对应审查意见**: 3.2 — D1多选在Markdown单元格中的分隔符未定义

**变更内容**:
- D1说明列追加：`多选用;分隔（如机械;化学）。选择最直接的失效机制，仅当确实无法单一归类时才多选`

### 改动3: D8 无临时处理方案时的填法

**对应审查意见**: 1.5 — 当故障无临时处理方案时如何填写未定义

**变更内容**:
- D8说明列追加：`若无临时处理方案，填写"临时处理：无，须立即停机处理"`

### 改动4: D5/D6 区分边界明确化

**对应审查意见**: 1.4 — D5(特征参数)与D6(监测手段)填写时易混淆

**变更内容**:
- D5说明列增加正误对照：`正确示例：[物理]振动速度>7.1mm/s。错误示例：振动加速度传感器（这是监测手段，应填D6）`
- D6说明列增加正误对照：`正确示例：[在线]振动加速度传感器。错误示例：振动速度>7.1mm/s（这是特征参数，应填D5）`
- JUDGE-FAULT模板新增第6项审查标准：`D5/D6区分正确性`

### 改动5: 来源引用规范落地到Prompt模板

**对应审查意见**: 3.1 — 2.3节要求"每轮输出必须包含来源引用"，但4.1节Prompt模板均未体现

**变更内容**:
- COLLECT-L1 新增要求5：`每条信息末尾用括号注明来源（标准编号/URL/文献名）`
- COLLECT-L2 新增要求9：同上
- COLLECT-L3 新增要求13：同上
- COLLECT-L4 新增要求8：`每条故障信息的D3列末尾用括号注明来源`

**涉及位置**: 1.3节知识维度表、COLLECT-L1/L2/L3/L4模板、JUDGE-FAULT模板

## v2.2 (2026-05-13)

基于电力行业构建过程中发现的设备层/部件层问题（详见 `docs/lessons_learned_equipment_component.md`），对构建流程做以下三项改进。

### 改动1: 阶段2增加设备分类决策文档（强制产出物）

**对应经验**: 规则前置 + 记录决策理由

**变更内容**:
- 新增步骤 2.5a: 编写设备分类决策文档
- 产出物: `equipment_classification.md`，记录每台设备的判定依据和关键边界决策
- 阶段2数据传递表增加 `equipment_classification.md` 产出
- 阶段2质量门控增加两项检查:
  - `equipment_classification.md 已编写`
  - `目录结构冻结`（通过后仅允许增量添加，不允许删除/合并/重命名）
- Judge审查时同步审查分类决策的合理性

**解决的问题**: 之前设备划分没有记录决策依据，导致同一问题（如凝汽器是否归属汽轮机）被重复争论，且LLM在无约束下自由划分产生结构混乱。

**涉及位置**: 步骤2.5a（新增）、步骤2.6质量门控（扩充）、数据传递表（更新）

---

### 改动2: 阶段2-4增加自动化校验脚本步骤

**对应经验**: LLM生成的数据有系统性重复缺陷

**变更内容**:
- 在"数据传递"章节后新增"自动化校验脚本"规范段，定义5项校验检查:
  | 校验项 | 适用阶段 | 不通过处理 |
  |--------|---------|-----------|
  | 行级去重 | 2-4 | 自动去重+警告 |
  | 表头完整性 | 2-4 | 阻断 |
  | 父部件引用完整性 | 3 | 阻断 |
  | 故障文件名对应 | 4 | 警告 |
  | 必填字段非空 | 3-4 | 警告 |
- 阶段2新增步骤 2.2a: 自动化校验（去重+表头）
- 阶段3新增步骤 3.2a: 自动化校验（去重+表头+父部件引用+必填字段）
- 阶段4新增步骤 4.2a: 自动化校验（去重+表头+文件名对应+必填字段）
- 阶段3/4质量门控增加 `自动化校验通过` 检查项
- 校验脚本指定为 `src/scripts/validate_kb.py`

**解决的问题**: 电力行业构建中发现44个文件、273行重复数据，全部未被LLM审查发现。自动化脚本以程序化方式检查，不依赖LLM，成本极低。

**涉及位置**: "自动化校验脚本"段（新增）、步骤2.2a/3.2a/4.2a（新增）、阶段3/4质量门控（扩充）

**代码实现**: `src/scripts/validate_kb.py` 已编写完成，支持以下用法：
- `python src/scripts/validate_kb.py --target src/data/power` — 全量校验
- `python src/scripts/validate_kb.py --stage 3 --target src/data/power/thermal/boiler` — 指定阶段校验
- `python src/scripts/validate_kb.py --target src/data/power --fix` — 自动修复重复行
- 首次全量校验结果：自动修复35条重复行，发现26个阻断错误（父部件孤立引用、表头格式），227个警告（必填字段为空、文件名不匹配）

---

### 改动3: 子设备拆分增加维度纯度审查

**对应经验**: 分类维度不能混用

**变更内容**:
- 步骤2.5（子设备拆分）增加"维度纯度要求"和"维度纯度自检规则":
  - 拆分必须基于单一分类维度（通常是技术路线）
  - 自检规则：任意两个子设备不应可能同时存在于同一台设备上（互斥性）
  - 列出常见正确维度选择（技术路线/机组类型/冷却方式）
- JUDGE-COMPLETENESS模板增加第6项审查标准:
  - "子设备维度纯度"：检查是否基于单一维度，是否存在维度混用

**解决的问题**: 锅炉sub_equipment.md曾混合了结构维度、循环维度、燃烧维度、用途维度等多个分类，产生22条互斥关系混乱的子设备条目。

**涉及位置**: 步骤2.5（扩充）、JUDGE-COMPLETENESS模板（扩充）
