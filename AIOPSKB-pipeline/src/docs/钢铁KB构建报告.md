## 二、机制沉淀（可复用到其他行业）

### 行业基础设施
- 行业名"钢铁"(目录`steel`)，config/slug_utils/md_to_json 三处映射补齐
- collector.py 钢铁 industry_anchor 分支（禁火电 DL/T + 禁石化 API/SH-T/GB30871，列 ISO 9908/YB/T/GB 50431 等）
- Kimi max_tokens 8192→16384（推理模型 JSON 截断根治）

### 构建链路（均验证）
- **C方案复用**（离心泵/风机/压缩机）：结构层复制石化 → 故障层钢铁 prompt 重生 → 三AI评审 → 治理链 → 工况清洗 → 导出
- **新生成**（轧机）：DeepSeek 结构生成 → 三AI评审 → 核心件补充 → 故障层(nohup) → 治理链 → 工况清洗 → 导出

### 钢铁治理脚本（src/scripts/，火电石化硬编码脚本不适用）
- `_fix_steel_cat_d1.py`：类别白名单+D1枚举通用映射
- `_fix_steel_pollution.py`：工况污染清洗（GB30871/API/SH-T/工况词）
- `_fix_steel_col_count.py`：列数错位修复（漏类别/|t|绝对值）

### 关键经验
- 评审机制：多轮辩论评分漂移，用 --rounds 1 单轮双AI（客观+省配额）
- 故障层 nohup：脱离 harness（turn结束不被kill），cron 监控
- 轧机粒度：方案B（产品子设备，机架位置D5标注），按§3.5故障机理同质性
- 子系统精简：≤6（避免部零件/故障重合）
