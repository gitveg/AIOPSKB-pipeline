## 一、故障属性维度（D1-D9）专项审查

### 1.1 D1 故障类别——枚举值设计问题 → 部分采纳（仅采纳分隔符规范化，其余不采纳）

**现有值**：机械 / 电气 / 绝缘 / 热 / 化学 / 控制 / 环境

**问题1：「绝缘」与「电气」存在包含关系** ~~→ 不采纳~~

~~绝缘故障本质上是电气故障的子类，但将其单独列出是合理的（因为绝缘故障有特殊检测手段和诊断体系）。然而，这引出一个**缺乏一致性原则**的问题：既然绝缘可以从电气中独立出来，"疲劳/蠕变"为什么不从机械中独立出来？"腐蚀"为什么不从化学中独立出来？当前枚举集的分类维度不统一（有的按物理现象、有的按工程学科）。~~

~~**建议**：明确枚举设计原则，并在说明列中写明"当故障同时符合多类时如何取值"。~~

> 📝 **主智能体评估**：审查者"绝缘是电气的子类"这一论断本身正确，但**不采纳合并建议**。理由：绝缘故障在工业 O&M 中有独立的检测体系（绝缘电阻、tanδ、局放）、独立的诊断方法和独立的检修规程（干燥、重绕），与通用电气故障（短路、断路、接地）的诊断链路完全不同。合并到"电气"会丢失这个工程区分度。这是一个**工程实用主义优于逻辑纯净性**的典型案例。疲劳/蠕变没有类似独立的检测/诊断体系，因此不单独列出——标准本身是一致的。

**问题2：「环境」作为故障类别语义模糊** ~~→ 不采纳~~

~~"环境"更像是**诱发因素**而非故障类型。环境恶劣会引发机械磨损、化学腐蚀、电气绝缘下降……它是触发条件，而不是失效模式类别。建议将其从D1中移除，改在D3的"诱发因素"中体现。~~

> 📝 **主智能体评估**：审查者对"环境"语义的分析准确，但**不采纳移除建议**。实际工业场景中，覆冰、沙尘堵塞、湿气凝露闪络等故障的直接物理机制确实无法完全归入机械/电气/化学中的任何一类。当前 v2.3 的 D1 说明已通过"选择最直接的失效机制，仅当确实无法单一归类时才多选"的规则来约束滥用。完全移除"环境"会导致部分故障无法归类。

**问题3：缺少「软件/固件」或明确归类说明** ~~→ 不采纳~~

~~现代工业设备大量引入PLC/DCS/边缘计算，软件逻辑错误、参数漂移、通信协议故障与"控制"类有交集但不完全等价。建议明确"控制"类别的边界是否涵盖软件层面。~~

> 📝 **主智能体评估**：审查者提出的问题是真实存在的，但**当前不采纳**。工业场景中软件=控制逻辑的载体，"控制"类别已可覆盖 PLC 逻辑错误、参数漂移等场景。如未来某行业（智能制造、航空航天）软件故障占比显著上升，可在该行业的阶段0初始化时扩展 D1 枚举，不在通用指南中预置。

### 1.2 D2 故障等级——缺乏判定标准 ✅ 已采纳 (v2.3)

**现有值**：轻微 / 一般 / 严重 / 危急

~~这四级等级合理，但**没有定义判定基准**。不同智能体（或不同人工审核者）可能对同一故障给出不同等级，导致数据不一致。~~

**采纳方案**：在 D1-D9 维度表后新增 D2 判定标准表：

| 等级 | 判定标准 |

| 危急 | 须立即停机，继续运行有人身安全风险或设备失效风险 |

| 一般 | 可在下次计划检修前处理，设备功能轻微降级 |
| 轻微 | 可在本检修周期内跟踪观察，不影响正常运行 |

~~当前链条：分类(D1)→理解(D3)→发现(D4)→检测(D5/D6)→诊断(D7)→处置(D8)→预防(D9)~~

~~这对预测性维护（PdM）至关重要。建议在D3中强制要求描述故障发展时间特征。~~

**缺失2：关联故障/级联风险（可选维度）** ~~→ 不采纳~~

## 三、可用性问题

### 3.1 来源引用无格式规范 ✅ 已采纳 (v2.3)

~~2.3节要求收集调研智能体"每轮输出必须包含来源引用"，但4.1节所有Prompt模板都没有要求输出来源，也没有定义来源引用格式。~~

**采纳方案**（与审查者原始建议有调整）：
- 审查者原建议：每个 COLLECT 模板末尾加独立的"来源引用"表格
- 实际采纳：采用更轻量的方案——在每条信息末尾用括号注明来源，如`（来源：DL/T 722）`。不放独立表格，避免额外 token 消耗
- COLLECT-L1/L2/L3/L4 四个模板各追加一条来源引用要求

> 📝 **主智能体评估**：审查者"Prompt模板缺少来源引用"的判断完全正确，这是一个重要的遗漏。但独立来源表格对 pipeline 执行而言过于重型——每轮 COLLECT 输出本身已是表格格式，再加一个独立来源表会导致输出复杂度显著上升且额外消耗一轮 LLM 调用。括号内联方案在信息可追溯性和执行成本之间取了平衡。

**同步位置**：`construct_guide.md` 4.1节 + `collector.py` L1/L2/L3/L4 四个模板
