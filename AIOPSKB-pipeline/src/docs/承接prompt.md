## 3. 火电做了什么（石化可直接复用的成果）

### 3.1 旋转机械"单设备+结构子设备"架构（★石化核心复用）

火电验证成熟：**故障机理通用的旋转机械，按"结构路线"合并为单设备**（而非按功能/系统合并），省 token 且诊断不损，工况特异在 D5 参数层标注。三个范例：

| 设备 | 子设备（结构路线） | 故障数 | 合并的工况 |
|------|------|------|------|
| 离心泵 | 卧式离心泵 / 立式筒袋泵 | — | 给水泵/循环水泵/炉水循环泵（卧式）+ 凝结水泵（立式）|
| 风机 | 离心风机 / 轴流风机 | — | 送风/一次风/小机组引风（离心）+ 大机组引/送风（轴流）|
| 压缩机 | 双螺杆压缩机 | 303 | 仪用/厂用压缩空气 |

> **石化泵/压缩机/风机种类远多于火电**，需按此范式决定设备粒度（见 §5 决策点）。

### 3.2 设备枚举治理（建 registry 必读）

火电 registry 曾混入大量"系统"后缀条目（功能域聚合），致粒度混乱+逻辑重合。治理判据（详见治理方案文档）：
- **设备层只含单体可独立检维修设备**（独立设备编号/独立停役/故障机理可独立描述）
- **三判据**：①重合性（被主设备/单体覆盖→删）②系统性（真系统→保留占位；异质设备群→拆）③同质性（A类拆分时，同质→合并为单设备+结构子设备）
- **三处置**：A拆分独立 / D去重删除 / 保留（真公用域/电气综合系统）
- **石化建 registry 时直接按此判据**，避免再产生"系统"层条目

### 3.3 治理方法（WARNING 治理路线，已验证）

真问题类型：D1非枚举/故障类别自创/D8级别缺/D5置信缺/检维修置信缺。治理=脚本批量（FIXES映射+补标注），每步 dry-run→apply→复验。
- `_fix_d1_cat_thermal.py`（D1/故障类别 FIXES 字典，**火电特有值持续积累**，石化可能需新增石化特有值）
- `_fix_d8_level.py`（D8级别，启发式：含标准号→规程级否则经验级）
- `_fix_d5_conf.py`（D5置信，参数末尾加置信）
- `_fix_maint_conf.py`（D11-15检维修置信，补"置信："前缀）

### 3.4 部件/零件层级标准（石化必须遵守）
- **判定准则（三是否）**：可独立拆卸 + 可独立故障 + 可独立更换/检修 → 记录；不可独立拆（拆了母件报废）→ 禁止出现
- **轴承方案B**：大型独立轴承=部件（零件列"—"）；嵌入式小轴承（齿轮箱/电机/泵轴承）= 零件
- **命名规范**：部件名禁带"总成"后缀；禁"XX本体"作零件；零件粒度止于可独立拆换件
- **零件行格式**：components.md 零件行**部件列填归属部件名**（非"—"）—— 火电压缩机曾因 DeepSeek 误填"—"致 validate 阻断错误

### 3.5 模型配置（config.py）
- `structure` = DeepSeek（Phase 3 结构生成）
- `collector`/`judge_b` = GLM（LITE_LLM_*，Phase 4 故障生成+审查）
- `verifier` = DeepSeek（**ENABLE_PHASE_C=False 当前关闭**）
- DeepSeek 配额省着用（仅 Phase 3 结构）；GLM 内容安全过滤（code 1301）拒的部件→临时改 collector+judge_b→DeepSeek 兜底，跑完改回

## 6. 关键技术约定（务必遵守）

1. **故障类别**只从 `failure_categories.yaml` 白名单选（禁自创）
2. **D1物理属性**：机械/电气/绝缘/热/化学/控制/环境
3. **17列故障表**：D1-D15 顺序固定；D11-D15 选填但须带置信标注
4. **部件/零件标准**：三是否判定；轴承方案B；禁总成后缀/本体零件/过度细化；**零件行部件列填归属部件名**
5. **故障跨层**：部件级只整体性失效，禁指向零件；因果链只挂根因
6. **三层结构**：子系统（无faults）→ 部件（总成级故障）→ 零件（具体失效）
7. **子设备划分**：单一维度（结构路线）/MECE/按存量裁剪
8. **设备层无"系统"条目**（§3.2）：单体设备或真公用域，避免功能域聚合
9. **编码**：段式，导出期生成，目录改名不破坏编码
10. **置信标注**：D5参数+D11-D15 每条带"置信：标准值/经验值/待核实"；禁伪造标准号
11. **命名**：部件/零件名禁"/"；跨子系统 MECE 不重复

## 8. 经验教训（风电+火电沉淀，石化避免重蹈）

1. **抽样≠批量**：单设备验证通过 ≠ 全量合规，必须全量 validate
2. **表面通过陷阱**：validate_stage3 针对子行业目录只查根目录**不递归 equipment 子目录** → 用 validate_kb.py `--target <设备目录>` 全量校验
3. **parse_md_table 静默丢数据**：表格行缺末尾 `|` 或列数不匹配 → 数据丢失只警告不报错，导出后用 _verify_xlsx 兜底
4. **harness 后台 bash 不稳定**（turn 结束被 kill）→ 长任务用 `nohup python ... > /tmp/x.log 2>&1 &` 脱离 harness；最后 1-2 条用前台阻塞跑（timeout 480s）确保完成
5. **fault phase 加速**：`--workers 3` 并行（单线程 6h → 并行 1.5h）；fault 默认跳过已生成，kill 后续跑只补未完成
6. **GLM 慢**（~2分钟/项，2轮）；GLM 内容安全过滤（code 1301）→ DeepSeek 兜底
7. **真实有效**：dry-run→apply→复验，关键改动加自检兜底，不接受表面通过/循环论证/数据污染
8. **设备粒度先决策**：旋转机械按结构路线合并（省 token 不损诊断），不要按功能系统拆碎

```bash

python src/scripts/validate_kb.py --target src/data/petrochemical/离心泵

python src/scripts/_fix_d1_cat_thermal.py src/data/petrochemical/离心泵
python src/scripts/_fix_d8_level.py src/data/petrochemical/离心泵 --apply
```
